# 摄影机与一屏标尺优化方案

## 决策

采用“固定世界高度、宽屏只扩展左右视野”的逻辑摄影机。地图单位与浏览器像素彻底解耦。

- 基准画面：16:9
- 基准世界范围：`180u × 101.25u`
- 角色高度：建议整理为 `10u`（现有 10.3u 可暂时保留）
- 21:9 宽屏：保持 `101.25u` 高度，宽度扩展至 `236.25u`
- 小于 16:9：优先信箱/裁切 UI 边缘，不增加垂直世界视野
- 大于 21:9：限制最大游戏视野，额外区域仅显示装饰背景或黑边

这样跳跃、落差、平台高度和敌人视野不会随浏览器窗口比例改变。

## 当前问题

地图把 `1672×941px` 当成固定战斗画面，并据此得到 `180×101u`；但本次 1280×720 运行环境中，实际 `.stage` 为约 `1169.8×512px`，宽高比为 2.285。若宽度仍是 180u，实际高度仅约 78.8u。

当前“真实场景”又直接使用 `1u = 9.29px` 放大到 929%，导致摄影机内容远大于地图中部视窗，切换后也无法自动对准关卡主体。

## 运行时换算

不要再通过显示宽度决定世界单位。以逻辑摄影机高度为基准：

```ts
const CAMERA_HEIGHT_U = 101.25;
const CAMERA_BASE_WIDTH_U = 180;
const CAMERA_MAX_WIDTH_U = 236.25;

const pxPerUnit = stageHeightPx / CAMERA_HEIGHT_U;
const visibleWidthU = clamp(
  stageWidthPx / pxPerUnit,
  CAMERA_BASE_WIDTH_U,
  CAMERA_MAX_WIDTH_U,
);
```

在本次 `1169.8×512px` 的运行画面中：

- `pxPerUnit ≈ 5.06`
- 可见世界高度始终为 `101.25u`
- 可见世界宽度约为 `231.36u`
- 角色、跳跃高度、平台落差都随同一比例渲染，不改变物理结果

## 模拟器的三个观察模式

### 1. 世界总览

- 适配完整地图宽高
- 显示区域、主路、捷径和能力链
- 不显示真实像素比例

### 2. 单区规划

- 自动适配选中区域
- 同时居中 X/Y
- 显示该区全部摄影机段、碰撞轮廓和区界过渡

### 3. 单屏预览

- 选中房间后，自动选择最近的 `CameraChunk`
- 预览缩放使用 `min(viewportW / cameraW, viewportH / cameraH)`，让整屏适配模拟器视窗
- 摄影机框外区域降低亮度，但不裁掉，方便观察前后屏衔接
- 提供“上一屏 / 下一屏”和 16:9、21:9 安全区切换
- 标尺显示世界单位和玩家身高，不再显示 929%

## 摄影机数据结构

```ts
type CameraChunk = {
  id: string;                 // T-01、T-02...
  zone: ZoneId;
  roomId: string;
  bounds: RectU;              // 摄影机允许活动的世界边界
  mode: "follow" | "rail" | "arena" | "boss" | "transition";
  rail?: PointU[];            // 竖井、斜坡、登山路的镜头轨道
  deadZone: RectRatio;        // 角色在画面内可自由移动的缓冲区
  lookAheadU: number;         // 面向方向的水平前视量
  lookUpU: number;
  lookDownU: number;
  lockOnEnter?: boolean;
  unlockCondition?: string;
  entryAnchors: string[];
  exitAnchors: string[];
};
```

## 五种摄影机模板

1. **横向探索**：角色位于画面 40%–45%，朝向侧增加前视量；用于城街、桥梁和主廊。
2. **竖向攀爬**：摄影机沿 rail 移动，禁止横向漂移；进入新平台后柔和吸附；用于矿井、钟楼和登天梯。
3. **战斗封锁**：踏入触发区后锁定固定 bounds，所有敌人必须位于 16:9 安全框内；战斗结束才解锁。
4. **Boss 房**：固定逻辑高度，限制宽屏扩展，避免宽屏提前看见 Boss 入场或场外对象。
5. **区界过渡**：在 1–2 屏范围内从旧摄影机 rail 混合到新区 rail，同时承担预加载。

## 地图房间与“一屏”的关系

房间不再等同一屏。一个房间可以包含多个摄影机段：

- 普通横廊：1–2 个 `CameraChunk`
- 长桥：2–3 个连续横向段
- 竖井/钟楼：2–4 个纵向段
- 战斗房：1 个锁定段 + 入口/出口缓冲段
- Boss 房：1 个独立固定段

“每区至少十屏”应按 `CameraChunk` 数量统计，而不是按房间数量或区域总宽度统计。

## 模拟器修改优先级

1. 移除“真实场景 = 929%”逻辑，改为“选中摄影机适配视窗”。
2. 把单一全局摄影机框改成每个房间的 `cameraChunks[]`。
3. 切换区域、房间或摄影机时自动居中 X/Y。
4. 加入 16:9 基准框、21:9 最大扩展框和 UI 安全区。
5. 在摄影机框内叠加玩家高度、跳跃包络线和安全落差线。
6. 加入检查：敌人、出生点、锁门、平台关键点不得落在摄影机安全区外。
