# 全图视觉与物理逻辑审查

审查对象：`/map` 剖面骨架 v0.2  
审查范围：7 区、77 个房间、30 个图例点、78 段地板、13 组建筑、8 座桥、16 组梯子、3 个升降梯

## 最高优先级问题

### P0 — 钩索获取形成循环门

- `t4 灯市屋脊` 标记 `lock: 钩索`。
- `mk5 钩索获取` 位于同一屋脊坐标附近 `(2200, 400)`。
- 另一个上层入口 `t7 商会阁楼` 同样需要钩索。

如果 `mk5` 是第一次获得钩索，则玩家无法进入获得钩索的区域。需要把获取点移到主街可达房间、首领奖励，或提供一条无需钩索的首次入口。

### P1 — 后续能力链缺少明确获取节点

- 震地击只有“验证”点，没有明确获取点。
- 闭息诀只有门，`腐花心室` 本身又要求闭息诀。
- 水行符只有门，`水下长廊` 和 `龙王水府` 都要求水行符。
- 二段跳只有“验证”点，没有首领奖励或拾取点。

当前无法证明主线能力图是无环的。建议把 `Room` 数据增加 `grants?: Ability`，把门统一为 `requires?: Ability[]`，对能力图做自动无环检查。

### P1 — 矿井升降机未接到实体下层平台

- 主升降井：`x=3680, y=520…980`。
- 熔炉实体地板：约 `x=3900…4130, y=1010`。
- 两者之间只有红色斜线路线，没有地板、桥或坡道。

视觉上“路线连通”，但玩家落地面并不连续。需要在升降梯底部增加实体平台/运轨桥，或把梯井移到熔炉西缘。

### P1 — 幽林盲道回程梯坐标不一致

- 文字、标记与路线使用 `x≈4930`。
- 实际梯子绘制在 `x=4830`。

相差约 100 地图单位，玩家会在标记处找不到梯子。应统一到同一 X 坐标，并让上下端落在 `y=730` 与 `y=1020` 的实体地板上。

### P1 — 缺少统一玩家物理标尺

设计文档明确把 player-scale silhouettes 放在 later，因此当前无法验证：

- 40–60 单位的梯端空隙是否可自动挂梯；
- 190–240 单位的平台水平间距能否跳过；
- 单向落差是否触发坠落伤害；
- Boss 门、房顶和走廊高度是否容纳角色与攻击动作。

在确定角色身高、站立碰撞盒、最大跳高、跑跳距离、二段跳距离、抓梯范围与安全坠落高度前，物理逻辑只能做拓扑检查，不能签署可玩性通过。

## 中优先级问题

### P2 — 绝顶与试剑峰的聚焦视图裁掉上层终点

分区聚焦固定使用 `scrollTop = 280 × zoom`。绝顶 Boss 位于 `y=110`，选中绝顶后 Boss 房和终点标记被裁到视图上沿之外；试剑峰也有同类问题。聚焦高度应根据该区最小 Y 动态计算。

### P2 — 行宫纵梯可能绕过水行符门

`x=7980` 的梯子从宴厅一直延伸到 `y=980` 水面附近，同时串联上层、主廊和水下入口。需要明确梯子在水位变化时是否可用；否则它可能绕过水下能力门。建议在水面处分段，或把下半段标为水行符解锁。

### P2 — 超长回城捷径不应画成空间直线

`(9870,170) → (2200,420)` 的虚线跨越几乎整个世界，会被理解为一条穿过所有区域的物理通道。如果它是传送、钟楼机关或快速旅行，应改用成对端点和非空间连接符号。

### P2 — 水下长廊使用“空中单位”语义不一致

`p4 水下长廊` 配置 `aerial`。如果该敌人实际是游鱼/水鬼，应建立 `aquatic` 类型；否则敌人行为与环境物理不一致。

### P2 — 矿井与幽林标记密度遮挡交通结构

55% 缩放时，升降井、回程梯、能力点和房间名互相覆盖。建议在低缩放隐藏次要文字，仅保留图标；放大到阈值后再显示完整标签。

## 已确认的优点

- 六个区域边界均有实体桥、洞口或闸门，不再只是抽象连线。
- 主线从山门到绝顶整体保持连续横向推进。
- 山门、旧城、矿井、幽林、天险的单向落口大多配有明确回程机制。
- 房间底部与地板 Y 坐标在大多数主轴房间中一致，Boss 房地板也基本对齐。
- 右侧说明补充了软锁与回程意图，便于后续数据化验证。

## 建议修复顺序

1. 先定义完整能力获取/门禁表，消除循环门。
2. 确定玩家物理标尺，并把它叠加到模拟器。
3. 修正矿井升降落脚面和幽林回程梯坐标。
4. 检查行宫纵梯与水位切换的状态图。
5. 修正上层区域的自动聚焦和低缩放标签策略。
6. 最后再细化敌人密度与镜头分段。

## 审查限制

本次依据当前代码数据和浏览器截图检查。没有可执行碰撞体、角色尺寸、跳跃曲线、水下移动参数、门状态机与存档恢复规则，因此未声称完成实际可玩性或无软锁证明。
