# 地图可读性与玩法部署审查 · 2026-08-04

## 审查范围

- 页面：`/map`，桌面视口 1280 × 720。
- 数据：`app/map/page.tsx`、`app/map/enemies.ts`、`docs/enemies.md`。
- 目标：验证地图是否能快速读出地形、路线、能力门和房间关系；检查敌人部署是否支持区域主题、教学顺序与难度曲线。
- 限制：当前房间只记录敌人类型，没有数量、位置、波次、触发器、巡逻范围和刷新规则，因此不能证明实战难度已经平衡。

## 总体结论

可读性比上一版明显提升：主路、捷径、传送、能力锁/奖励、房间类型、进出方向和敌人档案已经形成一套可维护的语言。敌人概念本身也有明确的动作、弱点和用途。

用户后续澄清：一个房间节点代表约一个屏幕或更大的连续区域，每区至少包含十屏空间，因此“70 / 77 节点有敌人”不能直接等同于战斗过密。本项撤回；后续应以每屏敌人数、波次、清场时长与两战之间的实际移动时间判断密度。

## 已确认优点

1. 地图语言完整：金实线、青虚线、紫色传送端点、锁与奖励有明确图例。
2. 建筑与交通可读：地板、梯子、升降井、桥梁、房屋和水面能与路线对照。
3. 房间详情补全了进入、离开、奖励和敌人，适合继续转成关卡表。
4. 敌人档案包含动作、反击窗口与玩法定位，已经不只是美术命名。
5. 区域特色组合中，矿井的“链狱卒 + 竖井”、暗渠的墨腹蛛、终局的无面剑侍都与空间目标一致。
6. 敌人层级筛选可用；关闭 8 种基础敌人后计数正确变为 6 / 14。

## 优先问题

### 已撤回 — 仅凭节点比例判断战斗过密

- 全图：77 个房间，70 个有敌人。
- 山门 10 / 11、旧城 11 / 12、矿区 11 / 11、幽林 10 / 12、天险 10 / 11、行宫 10 / 10、绝顶 8 / 10。
- 矿区和行宫没有 `save` / `hub` 节点，且都包含能力战或压轴战。

修正：节点是大尺度场景容器，不能由 `ROOMS[].enemies` 是否存在推断单位密度。本轮不减少战斗节点，改为补充数量、站位、波次、触发器和刷新规则后再评估。

### P1 — 水下敌人仍不符合物理语义

`水下长廊` 使用 `墨羽鸦 + 噬墨兽`，`月下祭坛` 使用 `湖中墨姬 + 墨羽鸦`。墨羽鸦的“俯冲/坠地”、噬墨兽的“撞墙眩晕”均按陆地/空中行为编写。

影响：水域视觉成立，但敌人的移动、受击和反击窗口没有水下版本，区域只换了背景，没有形成新玩法。

建议：增加 2 个基础水栖单位，例如“墨鳞游魂（环绕/冲刺）”与“沉甲鳖卫（贴底/水柱）”；湖中墨姬战不要再用墨羽鸦跟班，改用能被漩涡影响的水栖单位，或让分身本身承担杂兵压力。

### P1 — “提灯术士精英”与图鉴层级冲突

提灯术士在 `ENEMY_META` 中是 `basic`，但旧钟楼、孢囊温室、倒影宴厅均把它描述为能力奖励精英。

影响：侧栏按“基础/精英”筛选时，它被归为基础；玩家与设计人员也无法判断这些房间是同一基础 AI 的强化参数，还是独立精英版本。

建议：不要用文案临时升级。二选一：新增 `lantern_adept` 精英变体；或把房间部署改为结构化数据，增加 `role: leader`、`variant: elite` 和参数倍率。

### P1 — 终局 Boss 检验的能力与当前能力链不一致

无相殿主描述会复制“冲刺、墙跳、墨形”，但地图能力链是“钩索、震地击、闭息诀、踏云二段跳、水行符”。

影响：终局战无法成为玩家已学能力的总结考；也会让关卡能力门与 Boss 文档分裂为两套规则。

建议：先冻结唯一能力表。若保留当前地图链，Boss 二阶段应镜像钩索位移、震地波、二段跳与水镜/闭息状态；若要保留冲刺、墙跳、墨形，则应把它们正式加入地图获取链和回溯门。

### P1 — 当前部署数据不足以判断遭遇难度

`ROOMS[].enemies` 只记录敌人类型，无法区分 1 只与 6 只，也无法表达波次和站位。

影响：如“旧钟楼：术士 + 刀客 + 弩手”“试剑峰：校尉 + 弩手 + 墨鸦”可能是合理的分波教学，也可能是同时叠加的高压围攻，现有模拟器无法判断。

建议新增遭遇结构：`count`、`spawnGroup`、`wave`、`trigger`、`patrolRange`、`elevation`、`respawn`、`arenaLock`、`difficultyBudget`。地图至少显示数量、波次编号和站位范围。

## 中优先级问题

### P2 — 早期能力奖励战可能同时压制过多行动轴

- 旧钟楼：术士地面符阵 + 刀客近身 + 弩手远射。
- 试剑峰：赤枪校尉对空 + 弩手远压 + 墨鸦打断跳跃；玩家此时还没有二段跳。
- 月下祭坛：湖中墨姬幻身/漩涡 + 墨鸦空压。

建议：能力奖励战使用“主机制 + 一个辅助轴”。旧钟楼先清跟班再出术士；试剑峰把弩手设为开场可优先击杀，墨鸦只在二阶段少量加入；墨姬战取消墨鸦或改水栖单位。

### P2 — 55% 缩放下核心房间名仍然过小

地图整体缩放会把 11px 房名压到约 6px 的屏幕尺寸；侧栏和详情也大量使用 7–10px 文字。截图中结构比以前清楚，但普通房间名仍需靠近观看。

建议：房间名与敌人符号使用不随地图缩放的屏幕空间标签，最低保持 11–12 CSS px；详情辅助文字最低 11px。低缩放时可继续隐藏说明，但不要继续缩小关键名字。

### P2 — 左侧信息架构过长

分区、8 个图例、路线语义和 14 个敌人都堆在一个滚动栏内。720px 高度下敌人图鉴必须长距离下滚，选择敌人后分区入口离开视野。

建议：左栏拆成“分区 / 图层 / 敌人”三个标签页，或让分区列表与敌人筛选分别折叠；敌人档案选择后提供“定位到部署区”按钮。

### P2 — 右侧区域、敌人、房间详情竞争同一个长滚动栏

敌人档案、能力链、连接说明和房间详情串行堆叠，选择不同对象时上下文容易离开可见区。

建议：右栏改为固定标题 + `区域 / 房间 / 敌人` 三个页签；点房间或敌人时自动切换对应页签，而不是在长文档中插入新卡片。

### P2 — “沉水印”与三枚门印关系不清

终局门要求悬灯、赤铁、幽林三印，但行宫又发放“沉水印”，视觉上像第四枚同级门印；最终 Boss 战后再发“三印合一”也像一项迟到的能力。

建议：若沉水印不参与终局门，把它改名为“水镜信物/墨姬残印”并使用不同图标类别；“三印合一”应是祭坛开门状态，Boss 战后奖励改成“归途传送权限”。

## 推荐调整顺序

1. 先冻结能力表与印记规则，统一地图、敌人文档和终局 Boss。
2. 给 `ROOMS` 增加结构化遭遇数据，再谈数量与波次平衡。
3. 新增水栖基础敌人，替换水下墨鸦/噬墨兽。
4. 用每屏单位数、波次清场时间和移动间隔重新评估战斗密度。
5. 拆分左侧筛选与右侧详情信息架构。
6. 最后调整屏幕空间字号与低缩放显示策略。

## 审查步骤与健康度

1. 旧城总览与路线语义：良好；结构与路径层级清楚，房名偏小。
2. 敌人层级列表与档案：基本良好；档案完整，但层级语义有冲突。
3. 矿区剖面与首领房：高风险；空间主题匹配，但 11 / 11 战斗且无安全点。
4. 行宫水上/水下部署：高风险；地形可读，但水下敌人物理不成立，10 / 10 战斗且无安全点。
5. 绝顶与终局战：中风险；终局空间清楚，但 Boss 镜像能力与能力链不一致。
6. 敌人层级筛选：良好；交互和计数正确。
